## 빌드

`zig 0.16.0`, `--target=aarch64-linux-gnu.2.17`. CI 게이트 통과:

```
glibc versions needed: GLIBC_2.17     ← 2.17 초과 없음
defined FUNC symbols:  73
```

**2.17 하한은 편의가 아니라 강제 장치다.** `stat`/`fstatat`은 GLIBC_2.33+라 이 타깃에서는 **링크가 거부된다** — 인터포저가 stat 계열을 실수로 *호출*하는 것을 컴파일 시점에 막는다(R2). 이 빌드가 `stat` 미정의 참조로 실패하기 시작하면 그건 가드가 동작하는 것이니 하한을 올리지 말고 호출을 고칠 것.

## 검증된 설계 항목

| 항목 | 근거 |
|---|---|
| **정규화 → sysdir 순서** | `/proc/../etc/os-release`가 `ID=ubuntu`(게스트)를 반환. 순서가 반대면 Android의 `/etc`를 읽는다 |
| **`/proc/self/exe` 가상화** | `readlink /proc/self/exe` → `/bin/readlink` (로더 경로 아님) |
| **`getcwd` 역변환** | `cd /usr/bin && pwd` → `/usr/bin` |
| **`realpath` 역변환 + 억제** | `readlink -f /bin/sh` → `/usr/bin/dash` (호스트 접두사 없음) |
| **PATH 탐색이 게스트 네임스페이스** | `ldd --version` → `ldd (Ubuntu GLIBC 2.39-0ubuntu8.7)`. M4 이전엔 Android toybox가 잡혔다 |
| **exec 재디스패치** | 3단 중첩 bash, shebang, `#!/usr/bin/env` 모두 동작 |
| **shebang 단일 미분할 인자** | `#!/usr/bin/env sh` 처리 (Linux `binfmt_script` 의미론) |
| **`symlinkat` 비대칭** | target은 재작성 안 함, linkpath만 |

## 발견 1 — `alr_classify` 미링크로 전체 실패

`alr_elf.c`를 preload 빌드에 넣지 않아 `undefined symbol: alr_classify`로 모든 게스트가 죽었다. `scripts/build-preload.sh`의 `SRC`에 추가해 해결.

**교훈**: preload는 자기 완결이어야 한다. `src/common/`에서 가져오는 TU가 늘면 빌드 스크립트에 반드시 함께 추가한다.

## 발견 2 — `dlsym` NULL 호출은 진단 불가능한 SIGSEGV가 된다

`ls`/`find`/`apt-get`이 **출력도 오류도 없이** `rc=139`(SIGSEGV)로 죽는 구간이 있었다. 원인 후보가 NULL `real_*` 포인터였고, 다음을 추가했다:

- 모든 `real_*` 호출 앞 NULL 가드 → `errno=ENOSYS`로 깨끗하게 실패
- 바인딩 실패 심볼을 `g_missing`에 모아 `ALR_LOG=2`에서 출력

> ⚠️ **정직한 기록**: 가드 추가 후 증상이 사라지고 10/10 안정이지만, **진단 출력에 미바인딩 심볼이 하나도 없었다.** 즉 NULL 호출이 실제 원인이었다는 것이 확인되지 않았다. 스택 레이아웃 변화로 잠복 버그가 가려졌을 가능성을 배제하지 못한다.
>
> 가드 자체는 어느 쪽이든 옳은 방어 코드다(glibc 버전마다 심볼이 사라진다 — `__xstat` 계열은 2.33에서 없어졌고 `stat`/`fstatat`은 그때 생겼다). 그러나 **근본 원인 미확정을 리스크로 남긴다**: 재발하면 이제는 조용한 SIGSEGV가 아니라 진단 가능한 실패가 된다.

## 발견 3 — 게스트 DNS 불가 (Private DNS / VPN)

`apt update`를 시도하다 발견. 게스트의 이름 해석이 전부 실패하는데 **네트워크 자체는 정상**이다 (TCP 1.1.1.1:53 핸드셰이크 성공). 게스트가 8.8.8.8로 보낸 원시 DNS 질의는 **타임아웃**한다.

원인은 기기 구성: `UsePrivateDns: true` + `PrivateDnsServerName: 6cf6a6f2.d.adguard-dns.com` (DoT), 그리고 `com.adguard.android`의 VPN `tun0`. Android는 앱이 netd로 해석하기를 기대하고, bionic은 그렇게 한다(Termux `ping`은 정상). **glibc 리졸버는 netd를 모른다.**

초기 가설(`libnss_dns.so.2` dlopen 실패)은 **틀렸다** — glibc 2.34+는 `files`/`dns`를 libc에 내장해 dlopen하지 않으므로 로드 카운트 0이 정상이다. `LD_LIBRARY_PATH` 추가도 효과가 없었다(그래도 dlopen 일반을 위해 유지).

**해결: 리졸버 브리지.** `src/cli/alr_resolvd.c`가 `alr`(bionic) 안에서 스레드로 돌며 Unix 소켓을 연다. preload가 `getaddrinfo`/`freeaddrinfo`를 인터포즈해 그리로 넘기고, 서버는 **bionic `getaddrinfo`**를 호출하므로 netd·DoT·VPN을 그대로 존중한다. 브리지가 없으면(구버전 `alr`, 기동 실패) 게스트의 자체 리졸버로 폴백한다 — Private DNS가 없는 기기에서는 그쪽이 정상 동작하므로 하드 실패시키지 않는다.

`getaddrinfo`는 malloc한 리스트를 반환하는 계약이므로 이 경로에는 R1(no-malloc)이 적용될 수 없다. 핫패스가 아니라 이름 조회당 왕복 1회이므로 **의도적 예외**로 명시한다. `freeaddrinfo`도 함께 인터포즈해야 우리가 만든 것을 게스트가 올바로 해제한다.

> 남은 구멍: `getent hosts`는 `getaddrinfo`가 아니라 NSS `hosts` 백엔드를 직접 쓰므로 아직 실패한다. `res_*`를 직접 쓰는 `dig`/`nslookup`도 마찬가지다. `gethostbyname` 계열 추가가 남아 있다.

## 발견 4 — `mkstemp` 검증에서 잘못된 것을 쟀다 ⚠️ 방법론 교훈

중간에 `mktemp /tmp/aXXXXXX`가 **게스트 rootfs 안에** 파일을 만드는 것을 보고 "스펙 §6.14의 인터포즈 불가 주장은 틀렸다"고 결론 냈다. **그 결론이 틀렸다.**

- coreutils `mktemp`은 **gnulib의 자체 `gen_tempname`**을 쓰고, 그것은 **공개 `open`**을 호출한다 → 우리 `open` 래퍼에 잡힌다.
- apt는 **glibc의 `mkstemp`**을 쓰고, 그것은 `__gen_tempname` → **내부 별칭 `__open`**을 호출한다 → LD_PRELOAD로 잡을 수 없다.

증상이 정확히 그렇게 나왔다: `/var/cache/apt/srcpkgcache.bin`이 **ENOENT**(호스트에 그 디렉토리가 없음), `/tmp/apt.conf.XXXXXX`는 일반 실패(호스트 `/tmp`는 있으나 쓰기 불가).

**교훈**: 인터포즈 커버리지를 확인할 때 **실제 소비자와 같은 libc 경로를 쓰는 프로그램으로 재야 한다.** `mktemp` 명령으로 `mkstemp(3)` 커버리지를 잰 것은 처음부터 잘못된 대리 측정이었다.

`mkstemp`/`mkstemps`/`mkostemp`/`mkostemps`/`mkdtemp`(+`*64` 별칭)를 구현했다. 템플릿이 IN-OUT이므로 변형된 `XXXXXX`를 호출자 버퍼로 되쓴다. `rw()`가 원본 포인터를 그대로 반환한 경우(상대경로/sysdir/이미 rootfs 아래)에는 되쓸 것이 없다는 점이 핵심 분기다.

## 발견 5 — 중복 env 키: `getenv`는 첫 번째, bash는 마지막 ⚠️

`build_env()`가 상속 환경을 먼저 복사한 뒤 우리 값을 뒤에 붙였다. envp는 중복 키를 허용하고 **`getenv(3)`는 첫 번째 매치를 반환**하므로, 게스트의 모든 C 프로그램이 **Termux의 `PATH`**(`$PREFIX/bin`)를 봤다.

`bash -c 'echo $PATH'`로 확인했을 때는 정상으로 보였다 — **bash는 자체 테이블을 만들고 나중 할당이 이긴다.** 이 불일치 때문에 진단이 오래 걸렸다.

증상: dpkg가 `'sh' not found in PATH or not executable`을 7개 헬퍼에 대해 보고. 파일은 전부 존재하고 `test -x`도 통과하는데, dpkg의 `getenv("PATH")`만 Termux 경로를 보고 있었다.

수정: `PUT()`으로 넣을 키(`PATH`/`HOME`/`TMPDIR`/`ALR_ROOT`)를 상속 복사 단계에서 **먼저 제거**한다. `LD_PRELOAD`/`LD_LIBRARY_PATH`/`GLIBC_TUNABLES`에 이미 하던 것을 나머지에도 적용.

**교훈**: 게스트 환경을 검증할 때 **셸로 확인하지 말 것.** 셸의 변수 조회 의미론이 `getenv(3)`와 다르다. `env | grep ^KEY=`로 실제 envp를 봐야 한다.

## 미해결 — dpkg 언팩 (M6 다음 출발점)

`apt-get update`는 완주하고 의존성 해석도 되지만 `apt-get install git`이 dpkg 언팩에서 멈춘다. **다음 세션은 여기서 시작한다.**

### 좁혀진 사실

| 관측 | 결과 |
|---|---|
| `dpkg-deb --info` / `--fsys-tarfile` | ✅ 정상 (8,488,960 바이트) |
| `dpkg-deb -x` 로 추출 | ✅ **742개 항목 전부 추출 성공** |
| `dpkg --unpack libexpat1_*.deb` (신규 설치) | ✅ **언팩 성공** |
| `dpkg --unpack perl-base_*.deb` (**업그레이드**) | ❌ `error setting timestamps of '/usr/bin/perl.dpkg-new': No such file or directory` |
| 실패 후 `.dpkg-new` 잔해 | **없음** — 파일이 아예 안 만들어졌다 |
| 수동 재현 (`touch /usr/bin/zz.dpkg-new` + `touch -d`) | ✅ 둘 다 성공 |
| `libc-bin` postinst (`ldconfig`) | ❌ exit 1 (별개 블로커) |

**dpkg의 언팩 경로 자체는 동작한다** (libexpat1). 실패하는 것은 **기존 설치본 위의 업그레이드**이고, 그 경로는 백업(link/rename)을 더 탄다.

### 다음에 볼 것 (가설, 미검증)

1. **업그레이드 백업 경로** — dpkg는 기존 파일을 `.dpkg-tmp`로 옮기고 새 파일을 넣는다. 우리 `link()` copy-fallback이나 `rename()`이 이 순서에서 어긋날 수 있다.
2. **같은 deb 안의 하드링크 멤버** — `hrwxr-xr-x ./usr/bin/perl5.38.2 link to ./usr/bin/perl`. dpkg가 `perl.dpkg-new`를 만들고 그것에 링크를 거는 순서라면, copy-fallback이 아직 없는 파일을 복사하려다 실패할 수 있다.
3. **`posix_spawn` 미구현** — dpkg가 헬퍼를 그것으로 띄우면 자식이 후킹되지 않는다. (`dpkg-deb`는 후킹되어 동작하므로 주 경로는 `fork`+`execvp`로 보이나, 확인 필요.)
4. **`ldconfig` postinst** — `/etc/ld.so.cache` 쓰기. 별개로 처리해야 한다.

> 진단 방법 주의: `dpkg-deb -x`가 되는 것으로 "언팩이 된다"고 결론 내면 안 된다. dpkg의 `--unpack`은 **자체 tar 리더**를 쓰고 `dpkg-deb -x`와 다른 코드 경로다. 이 세션에서 `mktemp` 대리 측정으로 같은 실수를 이미 한 번 했다 (발견 4).

## 알려진 미구현 (M4 스펙 대비)

| 항목 | 상태 | 영향 |
|---|---|---|
| `/proc/mounts` 가상화 | **미구현** | 게스트 `mount`가 **호스트 마운트 테이블을 그대로 노출**한다 (`/dev/block/dm-33 on / type erofs …`). 호스트 정보 누출이며 스펙 §7 위반 |
| `/proc/self/status` 가상화 | 미구현 | `Name:` 이 `ld-linux-aarch6`로 보인다 |
| `/proc/self/cmdline` 가상화 | 미구현 | ld.so 트릭이 노출된다 |
| `dlopen`/`dlmopen` (§6.13) | 미구현 | Node 네이티브 애드온, Python C 확장이 깨진다 |
| `mkstemp` 계열 (§6.14) | **구현 완료** | 아래 "발견 4" 참조 — 스펙이 옳았고 중간 결론이 틀렸다 |
| `/dev/full` 에뮬 (§12) | 미구현 | doctor P9이 필요하다고 보고 |
| link2symlink (§8) | 미구현 | doctor P6이 필요하다고 보고. dpkg 무결성에 필수 |
| ioctl 번역 (§11) | 미구현 | readline/ncurses 심층 실패 가능 |
| `posix_spawn`/`system`/`popen` | 미구현 | 이들을 쓰는 게스트의 자식이 후킹 안 됨 |
| `gethostbyname` 계열 | 미구현 | `getent hosts`, `dig`, `nslookup` 은 아직 해석 실패 (`getaddrinfo` 는 해결됨) |

**M4/M5를 "완료"로 선언하지 않는다.** 핵심 경로는 동작하지만 위 목록, 특히 `mkstemp`와 link2symlink 없이는 M6이 진행되지 않는다.

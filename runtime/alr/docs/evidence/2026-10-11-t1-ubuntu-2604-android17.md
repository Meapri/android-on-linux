# T1 — Ubuntu 26.04 LTS 단일 지원, Android 17, glibc 2.42 termios와 ucf 환경 수정

- **날짜**: 2026-10-11
- **엔진 라벨**: `engine=alr`
- **기기**: Samsung SM-S937N (Galaxy S25 Edge), Snapdragon 8 Elite SM8750 (`ro.board.platform=sun`)
- **OS**: Android 17 (SDK 37), SELinux Enforcing, 커널 `6.6.127-android15-8-p33f4ffe-abogkiS937NKSUADZIF-4k`
- **컨텍스트**: `uid=10057  u:r:untrusted_app_27:s0  Seccomp=2` (Termux 0.118.3 GitHub 빌드, `targetSdk 28`, Termux sshd를 거친 셸)
- **빌드**: `alr`은 기기에서 Termux clang으로, `libalr_preload.so`는 zig 0.16.0으로 빌드했다(최종 preload sha256 `7b5cd340aa3b09e2…`, 호스트 게이트 10/10 PASS).
- **목적**: [ADR 0005](../../../../docs/adr/0005-termux-first-goals.md)의 T1(최신 LTS 기본값, 수용 테스트 FAIL 0)과 [ADR 0007](../adr/0007-android-16-only.md)의 "다시 볼 조건"(Android 17)

## 1. Android 17의 차단 syscall 집합

```
$ scripts/diff-sweep.sh docs/evidence/sweeps/snapdragon-8elite-android16-k6.6.txt \
                        docs/evidence/sweeps/snapdragon-8elite-android17-k6.6.txt
ALR SWEEP DIFF: IDENTICAL (239 syscalls, both devices)
$ scripts/diff-sweep.sh docs/evidence/sweeps/mediatek-mt8775-android16-k6.1.txt \
                        docs/evidence/sweeps/snapdragon-8elite-android17-k6.6.txt
ALR SWEEP DIFF: IDENTICAL (239 syscalls, both devices)
```

같은 기기가 Android 16에서 17로 업그레이드되었고, zygote 차단 집합 239개가 바뀌지 않았다. 이 결과로 `doctor`의 지원 릴리스에 17을 추가했다([ADR 0007 보론](../adr/0007-android-16-only.md)). 추가한 빌드의 `alr doctor` 결과는 `[P0 ] Android 17 (SDK 37) -> PASS (supported)`, `PASS=14 MITIGATED=4 EXPECTED=3 WARN=1 FATAL=0`, `VERDICT: READY`다. 남은 WARN은 P8(ssh 세션이라 `/dev/tty` 없음)이다.

## 3. glibc 2.42 이상에서 터미널이 터미널로 보이지 않았다

첫 26.04 수용 테스트에서 `ALR PTY TMUX`가 FAIL이었다(`no server running`). tmux 3.6의 패인 자식이 `tcgetattr(STDIN_FILENO)` 실패로 `_exit(1)`했다.

| 호출 (pty slave, 26.04, 수정 전) | 결과 |
|---|---|
| `ioctl(TCGETS)` PLT 경유 | 0 |
| `ioctl(TCGETS2)` PLT 경유 | 0 (기존 래퍼가 `TCGETS`로 번역) |
| raw `TCGETS2` | -1, `EACCES` |
| `tcgetattr` / `tcsetattr` | -1, `EACCES` |
| `isatty` | 0 |

glibc 2.42부터 `tcgetattr`, `tcsetattr`, `isatty`, `ttyname`이 libc 내부에서 `TCGETS2`를 쓴다. 내부 호출은 PLT를 거치지 않으므로 `ioctl` 래퍼에 닿지 않고, Android는 `TCGETS2`를 거부한다. glibc 2.39(24.04)는 `TCGETS`를 써서 문제가 없었다.

같은 버전에서 `speed_t`의 의미도 바뀌었다. 2.41까지는 `CBAUD` 코드(`B38400 == 017`)였고, 2.42부터는 baud 값 자체다(26.04의 `bits/termios-baud.h`에서 `#define B38400 38400U`).

수정(`src/preload/alr_preload.c`):

- `tcgetattr`, `tcsetattr`, `isatty`를 허용된 `TCGETS`/`TCSETS*`로 다시 구현했다. 속도 필드는 실행 중인 glibc 버전(`gnu_get_libc_version()`)에 맞춰 코드와 baud 사이를 변환한다. 코드가 없는 속도를 설정하려 하면 `EINVAL`이다(`BOTHER`는 `TCSETS2`가 필요하다).
- 기존 `ttyname_r` 래퍼는 glibc의 `ttyname_r`를 불렀다. glibc 2.42 이상에서는 tty 판정을 `TCGETS`로 하고 이름을 `/proc/self/fd/N`에서 읽는다.

수정 후 두 게스트 모두 `tty` → `/dev/pts/1`, `stty speed` → `38400`, `[ -t 0 ]` 참, Python `os.ttyname(0)`과 `os.isatty(0)` 정상이다. 수용 테스트에 `ALR PTY TERMIOS`, `ALR PTY TTYNAME`, `ALR PTY SPEED`를 추가했다.

## 4. ucf가 환경을 비우면 자식이 가상화 밖에서 돌았다

26.04에서 `apt-get install php-cli` 등의 설정 단계가 실패했다. ucf 3.0052는 자기 자신을 `env -i`에 가까운 깨끗한 환경으로 다시 실행하고, 이때 `ALR_ROOT`, `ALR_FAKEROOT` 같은 런타임 변수도 사라진다. 그 자식은 경로 가상화 없이 실제 uid로 실행되어 `/etc/ucf` 같은 경로를 Android 쪽에서 찾았다.

수정(`src/preload/alr_preload.c`): preload가 초기화할 때 런타임 변수 9개(`ALR_ROOT`, `ALR_LDSO`, `ALR_LIBPATH`, `ALR_PRELOAD`, `ALR_FAKEROOT`, `ALR_COUNT`, `ALR_LOG`, `ALR_LOG_FD`, `ALR_RESOLV_ENV`)를 저장해 둔다. `execve` 래퍼는 새 환경에 같은 이름이 없으면 저장한 값을 덧붙인다. 게스트가 직접 설정한 값은 덮어쓰지 않는다.

수정 후 `ALR_FAKEROOT=1 alr run /usr/bin/env -i /usr/bin/id -u`가 `0`을 출력하고, ucf, php, mercurial, sysstat, parallel의 설정 단계가 통과한다. 수용 테스트에 `ALR ENV SCRUB KEEPS RUNTIME`을 추가했다.

## 5. 24.04 지원 중단

[ADR 0005](../../../../docs/adr/0005-termux-first-goals.md)의 게스트 정책에 따라 `alr`이 지원하는 게스트는 26.04 하나다.

- 배포판을 지정하지 않은 명령은 설치된 트리와 상관없이 항상 `ubuntu-26.04`를 쓴다. 기기에 24.04 트리가 남아 있는 상태에서 `alr config`가 `default_distro ubuntu-26.04`, `alr run`이 `Ubuntu 26.04.1 LTS`를 보고했다.
- `SHA256SUMS`에 닿지 못하면 어떤 릴리스든 `discovery-failed`로 멈춘다. 24.04에만 있던 해시 없는 폴백 이름을 지웠다.
- `-d ubuntu-24.04`처럼 이름을 주면 실행은 되지만 검증하지 않는다.

## 6. 수용 테스트와 호환성 폭

최종 빌드로 배포판을 지정하지 않고 돌렸다(`ALR_DISTRO` 없음, 기본값 26.04). 미리 넣은 패키지는 `git python3 libc6-dev gcc make tmux bind9-dnsutils`와 `alr install --with node,codex`다. 원본 출력: [26.04 수용 테스트](2026-10-11-t1-acceptance-ubuntu-26.04.txt), [26.04 호환성 폭](2026-10-11-t1-breadth-ubuntu-26.04.txt).

| 게스트 | PASS | FAIL | KNOWN_FAIL | SKIP |
|---|---:|---:|---:|---:|
| Ubuntu 26.04.1 (glibc 2.43), 최종 | 169 | 0 | 1 | 0 |
| Ubuntu 24.04.4 (glibc 2.39), 지원 중단 전 마지막 실행, §4 수정 전 | 163 | 2 | 1 | 1 |

24.04 행은 termios 수정이 glibc 2.39에서 회귀를 만들지 않았다는 기록으로만 남긴다([원본](2026-10-11-t1-acceptance-ubuntu-24.04.txt)). 이후로는 재지 않는다.

- `KNOWN_FAIL`은 `/dev/full`(비목표) 하나다.
- `SKIP`이던 `CLI VERSION DETECTS STALE PRELOAD`는 비교할 두 번째 `.so`를 `$PREFIX/share/alr`에서 찾았기 때문에 dev 배포에서는 늘 건너뛰었다. `alr version`은 해시만 비교하므로, 이제 게스트 `.so`에 바이트를 덧붙인 사본을 잠시 끼워 넣고 검사한다. 원본 복원은 `CLI VERSION TEST RESTORED`가 확인한다.
- `ALR CODEX FINDS GUEST GIT`, `ALR CODEX FINDS GUEST RG`는 FAIL이었다. `--with codex`가 받은 codex 0.162.1의 `codex doctor`는 git과 rg를 실행하지 않고 "found; execution not verified"만 출력해서, 검사가 찾던 `git version 2.`와 `ripgrep `가 출력에 없었다. 기대값을 발견 문구(`git executable found`, ``(system, `rg`)``)로 바꿨다. 실행 확인이 빠지지 않도록 hostbin의 rg를 직접 실행하는 `CLI HOSTBIN RUNS GUEST RG`를 추가했다(git은 기존 `CLI HOSTBIN RUNS GUEST TOOL`).
- `ALR GIT VERSION`은 24.04의 `2.43.0`으로 고정되어 있었다. 같은 스위트의 node 검사처럼 형식(`^git version N.N`)만 확인하도록 바꿨다.
- 경로 불변식은 그대로다: `path_traps=0 syscall_stops=0`.

호환성 폭은 `install=96/96 run=96/96`이다. 26.04에서 이름이 바뀐 패키지 두 개를 `tests/device/breadth.sh`에서 고쳤다(`dnsutils` → `bind9-dnsutils`, `p7zip-full` → `7zip`). php-cli는 preload 심볼 수에 민감했지만([M14 §2](2026-08-03-m14-ioctl-php.md)), 169개에서도 동작한다.

## 7. 남은 것

- **T1 완료 기준을 채웠다**: 기본값이 최신 LTS이고, 수용 테스트가 `FAIL=0 SKIP=0`이며, 남은 `KNOWN_FAIL`은 비목표인 `/dev/full` 하나다.
- pty 안의 다른 glibc 내부 ioctl(`tcgetsid`의 `TIOCGSID` 등)도 같은 이유로 래퍼를 우회할 가능성이 있다. 확인하지 않았다.
- `ALR_ROOT_DIR`에 `..`가 들어 있으면 `getcwd` 역변환이 어긋나 수용 테스트 5건이 실패했다. 정규 경로로 다시 돌려 통과했고, 이 입력을 정규화하는 수정은 하지 않았다.
- MediaTek 참조 기기에서는 재지 않았다.

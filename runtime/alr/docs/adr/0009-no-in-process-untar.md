# ADR 0009 — 자체 untar 를 만들지 않는다

- 상태: **Accepted**
- 날짜: 2026-08-04
- 관련: [05-provisioning-spec.md §2](../05-provisioning-spec.md), [ADR 0004](0004-link2symlink.md)

## 맥락

[05 §2](../05-provisioning-spec.md) 는 `src/cli/alr_untar.c` 라는 파일 이름과 함께 안전 추출 규칙 아홉 개를 적어 두었다. 그 파일은 존재한 적이 없다. `alr install` 은 GNU tar 를 플래그와 함께 호출하고, 추출 후에 몇 가지를 손본다.

규칙별로 지금 무엇이 그것을 만족하는지 실제로 따져 보면 이렇다.

| §2 규칙 | 무엇이 만족하는가 |
|---|---|
| 절대경로 멤버 거부 | GNU tar 기본값 — `-P` 없이는 선행 `/` 제거 |
| `..` 컴포넌트 거부 | GNU tar 기본값 — 해당 멤버를 거부 |
| blk/chr/fifo/socket 스킵 | 비루트에서 `mknod` 가 `EPERM`. tar 가 경고하고 넘어간다. 더해 `--exclude=dev/*` |
| `chown`/`lchown` 절대 호출 안 함 | `--no-same-owner`, 그리고 비루트라 애초에 불가 |
| setuid/setgid 마스킹 | 추출 후 `find -perm /6000 -exec chmod a-s` |
| xattr 스킵 | 스톡 tar 는 `--xattrs` 없이는 복원하지 않는다 |
| 하드링크 멤버 복구 | `fix_hardlinks()` — [§B6](../01-platform-facts.md) |
| 임베디드 NUL 이름 거부 | tar 헤더가 NUL 종료 필드라 표현 불가 |
| **링크 타깃이 추출 루트를 벗어나면 거부** | **아무것도 만족하지 않았다** |

마지막 하나가 진짜 구멍이었다. GNU tar 는 심링크 **타깃**을 검사하지 않는다 — `x -> ../../../etc/passwd` 를 적힌 그대로 만든다. 정상 동작이다(추출 시점에 해석되지 않는다). 하지만 게스트 안에서 그 링크를 따라가면 rootfs 밖으로 나간다.

## 결정

**자체 untar 를 만들지 않는다.** 대신 위 표의 마지막 줄을 추출 후 검사로 닫는다.

### 자체 untar 를 만들지 않는 이유

**의존성이 늘어난다.** tar 멤버를 직접 읽으려면 gzip 을 직접 풀어야 한다. zlib 를 링크하면 `alr` 은 지금까지 유지해 온 "libc 외 의존성 없음" 을 잃는다. 재현 가능 빌드([§1](../04-preload-spec.md))의 표면이 넓어지고, 릴리스 tarball 이 검증해야 할 것이 하나 더 생긴다.

**가장 안전에 민감한 코드 경로에 새 버그 표면을 만든다.** 600줄쯤의 새 파서가 대체하는 것은 30년 묵은 GNU tar 다. traversal 방어를 직접 짜겠다고 파서를 새로 쓰는 것은, 방어 하나를 얻으려고 파싱 버그 전체를 새로 떠안는 거래다.

**남은 위협이 크지 않다.** 기본 경로는 `SHA256SUMS` 로 검증된 공식 ubuntu-base 다 — 거기엔 탈출 링크가 없다(실측: 20개 절대 심링크 전부 상대화, 탈출 0). 악성 아카이브가 들어올 수 있는 경로는 사용자가 직접 지정하는 `alr install --url` 하나뿐이고, 그 사용자는 이미 자기가 고른 tarball 을 자기 기기에 푸는 중이다. 게다가 `alr` 은 **보안 경계가 아니다**([00 §1](../00-product.md)) — 게스트는 Termux uid 로 돌고 Termux 가 닿는 모든 것에 닿는다. 탈출 심링크가 열어 주는 것은 게스트가 다른 방법으로 못 하던 일이 아니다.

그래도 닫는 이유는 **조용하기 때문**이다. rootfs 안에 있다고 믿은 경로가 밖을 가리키는 것은 이 프로젝트에서 가장 비싼 버그 부류다.

### 대신 무엇을 하는가

`relativize_tree()` 는 이미 트리 전체를 걸으며 절대 심링크를 상대화한다. 같은 순회에서 **상대 타깃**을 어휘적으로 검사한다: 링크가 든 디렉토리가 루트에서 `depth` 만큼 내려와 있으니 `..` 하나가 한 칸 올라간다. 어느 지점에서든 음수가 되면 탈출이다. 해당 심링크를 지우고 `reason=extract-traversal-reject` 로 설치 전체를 실패시킨다.

**어휘적 검사가 옳은 이유**: 중간 컴포넌트가 지금 존재하는지와 무관해야 한다. 나갔다 들어오는 타깃도, 중간 컴포넌트 자체가 심링크라면 밖에서 해석된다.

`fix_hardlinks()` 는 이름과 타깃 **양쪽**을 검사한다. 하드링크는 심링크와 달리 **만들고 나면 진짜와 구별되지 않는다** — 사후 검사로 되돌릴 수 없으므로 만들기 전에 막아야 한다.

## 결과

- `src/cli/alr_untar.c` 는 만들지 않는다. [05 §2](../05-provisioning-spec.md) 는 요구사항 목록으로 남고, 각 줄이 **무엇으로** 만족되는지를 함께 적는다.
- `extract-traversal-reject` 가 reason 어휘로 돌아온다. 이 코드는 예전에 "구현되지 않은 기능의 코드" 로 삭제됐었고, 05 §7 은 *"그 기능이 들어오면 코드와 함께 이 목록으로 돌아온다"* 고 적어 두었다. 그대로 됐다.
- `tests/device/install_gate.sh` 가 탈출 심링크를 담은 tarball 을 만들어 거부되는지 확인한다 — 규칙을 적어 두기만 하고 위반 사례를 한 번도 통과시켜 본 적 없는 상태로 두지 않는다.

## 대안

**zlib + 자체 tar 파서.** 위의 이유로 기각. 원래 이 ADR 이 없어서 "언젠가" 로 남아 있던 것이 바로 이 대안이다.

**`tar --absolute-names` 금지에만 의존.** 이미 기본값이고, 링크 타깃 문제를 전혀 건드리지 못한다.

**libarchive 링크.** zlib 보다 큰 의존성이고 같은 반대 이유가 그대로 적용된다.
